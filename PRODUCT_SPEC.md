# TRACK A — Import fidelity: same size everywhere

## A.1 What is true today

| Fact | Anchor |
| --- | --- |
| Project size comes from `<scene width>` / `<scene height>` only | `src/engine/amXmlCodec.ts:599–600` |
| Missing attributes silently default to **1080 × 1080** | same lines (`\|\| '1080'`) |
| `exportWidth` / `exportHeight` are written on export but **never read** on import | `amXmlCodec.ts:140` vs `599` |
| Text layers get `wrapWidth: projW * 0.85` — a hardcoded box, not the project's text frame | `amXmlCodec.ts:581` |
| Preview canvas backing store = `project.width × previewScale` (no DPR) | `renderer.ts:993–995`, `EditorScreen.tsx:99` |
| Canvas is CSS-stretched to the stage (`width:100%`) | `PreviewCanvas.tsx:383–388` |
| `acScreenSize` = **project size**; `acPreviewSize` = **render pixels** | `renderer.ts:1916–1918` |
| Effect params are in project units; screen-space math uses `acScreenSize` | same |

Two real defects fall out of that table:

**A-1 · A project with no `width`/`height` on `<scene>` imports as 1080×1080.** Every coordinate is then
wrong by the aspect ratio, and nothing warns the user. This is the most likely cause of "the import is
the wrong size".

**A-2 · Preview resolution ≠ project resolution.** `previewScale` shrinks the backing store while
`acScreenSize` stays in project units. Effects that mix the two (`acPreviewSize`, `1.0/getTexSize(...)`
texel math, `gl_FragCoord`-based sampling) render at a different *scale* in preview than in export —
so the preview lies about the result. On a 2× display the canvas is also upscaled by CSS, which makes
the whole stage feel soft and small.

## A.2 Size resolution ladder (must be exact — no silent defaults)

Import size resolves in this order, and **fails loudly** if none apply:

| Priority | Source | Condition |
| --- | --- | --- |
| 1 | `scene@exportWidth × scene@exportHeight` | both present, integers > 0 |
| 2 | `scene@width × scene@height` | both present, integers > 0 |
| 3 | `scene@aspect` ratio applied to a sane base | e.g. `9:16` → `1080×1920` |
| 4 | **Abort** with `Project size not declared in XML` | never guess 1080×1080 |

Additionally:

- Reject any dimension outside `16 … 8192`, and any aspect outside `1:8 … 8:1`, with a named error.
- Round to even integers (video encoders require it) and state the rounding in the import report.
- Surface an **import report** — size, fps, duration, media found, media missing, text boxes defaulted —
  so the user sees what the importer decided. No silent decisions anywhere.

## A.3 Coordinate space contract

One rule, applied everywhere:

> **Project units are the only coordinate space.** Project size is `(width, height)` in those units.
> Nothing normalizes, nothing rescales by device, DPR, or preview zoom.

Enforced by:

1. `acScreenSize`, `acLayerSize`, `acLayerCenter` → always project units (already true,
   `renderer.ts:1916–1920`).
2. `acPreviewSize` → **render target pixels**, and any effect that uses it must be given the *project*
   scale instead. Audit: replace every `acPreviewSize` read in the 315 shaders' semantics with an
   equivalent in project units, or feed `acPreviewSize = project size` and keep a separate
   `acRenderSize` for the few internal passes that genuinely need pixels.
3. Text: `wrapWidth` must come from the XML text frame when present; the `projW * 0.85` default is a
   *labelled* fallback in the import report, not a silent one.
4. Zoom is a view transform only (`previewZoom`), never a data change.

## A.4 Preview resolution (the DPR fix)

```
backingW = round(project.width  × previewScale × min(devicePixelRatio, 2))
backingH = round(project.height × previewScale × min(devicePixelRatio, 2))
canvas.style.width  = stageW px
canvas.style.height = stageH px
```

`previewScale` remains the user's quality knob (0.25 / 0.5 / 1.0). DPR multiplication caps at 2 to keep
4K projects from allocating 8K buffers. The point is that at `previewScale = 1` on a 2× display the
canvas is *native*, not stretched.

Mouse mapping already normalises by `getBoundingClientRect()` and `project.width`
(`PreviewCanvas.tsx:117–118`) so it survives this change untouched.

## A.5 Verification matrix (the acceptance test for "no difference")

| Step | PC | Phone | Web | Tolerance |
| --- | --- | --- | --- | --- |
| Import the same share link | ✔ | ✔ | ✔ | — |
| Read reported composition size | screenshot | screenshot | import report | **exact match** |
| Render frame 0 at 100 % zoom | screenshot | screenshot | screenshot | **0 px** difference in a 500×500 test square's edges |
| Export 1 frame at project size | PNG | PNG | PNG | identical pixel dimensions |
| Text layer line breaks | screenshot | screenshot | screenshot | same line count, same break positions |

Run it for these four project shapes: **1080×1080, 1080×1920, 1920×1080, 3840×2160**. The 4K case is the
one that catches unit bugs, because a 1080-normalized pipeline shows up as a 4× error there and nowhere
else.

## A.6 Risks

- If AM's XML is 1080-height-normalized rather than project-pixel, layer coordinates must be multiplied
  by `height / 1080` on import. **Measure before assuming** — the matrix in A.5 decides it in one run.
- Old projects in local storage were imported with the silent 1080×1080 default. On import-report
  rollout, detect square-ish projects whose layers extend past `height` and offer a re-import.

# TRACK B — Native feel: the website should read as the app

The APK has already been reverse-engineered into `src/generated/`:

| Asset | Size | Use |
| --- | --- | --- |
| `arsc_tokens.json` | 319 KB | exact ARSC colour/spacing/int tokens |
| `layout_inventory.json` | 306 KB | every APK layout, its tags and attributes |
| `icons.json` | 424 KB | 374 vector icons |
| `src/styles/tokens.css` | 177 lines | already carries the A1–A12 palette, accent ramp, timeline track gradients |

So "feel" is not a matter of taste here — it is a **fidelity target with a source of truth.**

## B.1 What makes it feel like a website instead of the app (current gaps)

1. **No motion language.** Panels appear; nothing eases. The APK opens sheets, ripples on tap, and
   settles selection handles.
2. **Touch geometry is web-sized.** Tap targets below 44 px, spacing not on a grid.
3. **No bottom-sheet behaviour.** Effect settings, move/transform, blending are panels; in AM they are
   draggable sheets with peek/mid/full snap points.
4. **No selection affordances.** AM has a gizmo with handles, a bounding box with corner radii, and a
   long-press context.
5. **Timeline has no physics.** No inertia scroll, no snap-to-keyframe, no pinch-zoom on the ruler.
6. **No feedback loop for actions.** AM confirms with a ripple, a haptic tick and a transient label.

## B.2 Motion system (single source of truth)

| Token | Value | Used for |
| --- | --- | --- |
| `--am-dur-instant` | 90 ms | ripple, press |
| `--am-dur-fast` | 160 ms | chips, toggles |
| `--am-dur-base` | 220 ms | sheets, dialogs |
| `--am-dur-slow` | 320 ms | screen transitions |
| `--am-ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | everything that enters |
| `--am-ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | everything that leaves |
| `--am-ease-sheet` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | sheet drag/settle |

Rules: nothing animates longer than 320 ms; no animation on the render loop; every transition must be
interruptible (drag cancels an in-flight sheet animation); `prefers-reduced-motion` collapses all of it
to `--am-dur-instant` with no translation, only opacity.

## B.3 Component behaviour parity

| Component | APK behaviour | Web target |
| --- | --- | --- |
| Effect settings | bottom sheet, 3 snap points (peek 25 %, mid 55 %, full 90 %), drag handle, backdrop dims with scroll | same, with the snap physics above |
| Add layer | bottom sheet with icon rows, not a centred modal | bottom sheet |
| Long press on layer | context menu anchored to the touch point | same, 400 ms hold, no text selection |
| Timeline scrub | drag anywhere on the ruler; playhead magnetises to keyframes within 6 px | same |
| Pinch on timeline | horizontal zoom around the pinch centroid | same, with wheel+ctrl equivalent on desktop |
| Selection gizmo | corner handles (rotate/scale), centre handle (move), dashed bounding box | same geometry, 44 px hit boxes |
| Tap feedback | ripple from the press point, 90 ms | same |
| Toast | transient label at the bottom, 1.8 s, non-blocking | same |

## B.4 Typography and grid

- UI font: **Hind** (bundled, `public/am/fonts`); numerals and labels fall back to Roboto per the ARSC
  families.
- Spacing on a **4 px grid**; component heights `28 / 36 / 44 / 56`; radii `4 / 8 / 12 / 16 / 999`.
- Text sizes `11 / 12 / 13 / 14 / 16 / 20` with 1.25 line-height; no font bigger than 20 in chrome.

## B.5 Acceptance

- Side-by-side recording of the same interaction (open effect panel, scrub, add effect) against the
  APK; the sequence of states and the timing of each transition match within **±40 ms**.
- Every interactive target measures ≥ 44 × 44 CSS px on touch (≥ 28 px height on desktop per Track C).
- `prefers-reduced-motion` honoured in every animated component — verified by toggling the OS setting.
- No layout shift greater than 4 px during any transition.

# TRACK C — Desktop: bigger, denser, keyboard-first

Two complaints, two separate fixes:

- **"Too small"** → the stage and chrome do not scale with the window. Fix: layout + UI scale.
- **"Not compact"** → mobile-sized rows in a desktop grid. Fix: density tokens.

## C.1 Density system

Add to `tokens.css`:

```css
:root {
  --am-ui-scale: 1;          /* 0.8 – 1.25, user setting */
  --am-row-h: 34px;          /* compact: 28, comfortable: 40 */
  --am-gutter: 12px;         /* compact: 8, comfortable: 16 */
  --am-pad: 10px;            /* compact: 6,  comfortable: 14 */
  --am-font-ui: 13px;        /* compact: 12, comfortable: 14 */
  --am-icon: 18px;           /* compact: 16, comfortable: 20 */
  --am-radius: 8px;
}
```

All chrome sizes derive from these six values — no hardcoded pixel rows. A single
`data-density="compact|comfortable"` attribute on `<html>` switches the set, and `--am-ui-scale`
multiplies the whole chrome with `calc()`.

Defaults by breakpoint:

| Viewport | Density | UI scale | Rationale |
| --- | --- | --- | --- |
| `< 768 px` | comfortable | 1.0 | touch, Track B applies |
| `768–1279 px` | compact | 1.0 | tablet/small laptop |
| `≥ 1280 px` | compact | **1.1** | the "too small" fix — chrome grows, content stays dense |
| `≥ 1920 px` | compact | 1.15 | large monitors |

## C.2 Layout

Three-pane at `≥ 1280 px`, one pane below:

```
┌──────────────────────────────────────────────────────────────┐
│ action bar   (project · undo/redo · export · settings)        │
├───────────────┬──────────────────────────────┬───────────────┤
│ LAYERS        │  STAGE (canvas, fit-to-view)  │ INSPECTOR     │
│ 260–420 px    │  flexible                    │ 300–460 px    │
│ resizable     │  zoom controls bottom-right  │ tabs: props / │
│               │                              │ effects / etc │
├───────────────┴──────────────────────────────┴───────────────┤
│ TIMELINE   (resizable height 140–420 px, ruler + tracks)      │
└──────────────────────────────────────────────────────────────┘
```

Rules:

- Every splitter is draggable and persisted (`am.layout.v1` in localStorage).
- Panes collapse to icon rails (`Ctrl+1/2/3`), stage re-fits on any resize (`F`).
- Stage zoom: wheel = zoom at cursor, `Ctrl+wheel` = pan, fit button, numeric zoom field, `0` = 100 %.
- Nothing below 1280 px gets the three-pane layout; it stays sheet-based.

## C.3 Keybindings

Global handler replaces the current four-case listener in `EditorScreen.tsx:179–208`. Rules:

1. One handler, `keydown` on `window`, capture phase.
2. **Ignore entirely** when the event target is `input`, `textarea`, `select`, `[contenteditable]`, or
   inside an open dialog (except `Escape`).
3. Normalise `Ctrl`/`Cmd` to `Mod`; display the platform glyph.
4. Never bind a browser-ownable chord (`Ctrl+W`, `Ctrl+T`, `Ctrl+N`, `Ctrl+Shift+N`, `F5`, `Ctrl+R`).
5. Every binding must be discoverable: hold `?` → shortcut overlay listing them, grouped.
6. Rebindable; stored in `am.keymap.v1`; "reset to defaults" always present.

## C.4 Acceptance

- Every action in the table is reachable by keyboard alone; a Playwright pass walks the table and asserts
  each one fires its store action once.

- `am.layout.v1` and `am.keymap.v1` survive reload; "reset" restores documented defaults.

# TRACK D — Custom Effects: XML in, effects only

Community workflow: people generate effect XML with other AIs and paste it in. That is useful **only if
the payload is constrained to an effect** — otherwise it is an arbitrary-code channel into the editor.

## D.1 Entry point

In the Effects browser, a new top-level tab: **Custom**, containing "Import effect XML".
Accepted via paste box, file picker (`.xml`), or drag-and-drop. One file at a time.

## D.2 Accepted input — and nothing else

| Input | Result |
| --- | --- |
| `<effect id="…">…</effect>` (one root) | ✅ accepted |
| `<scene>` / project XML | ❌ `This is a project file, not an effect.` |
| `<presets>` / `<preset>` | ❌ `Preset packs are not supported here.` |
| `<shapes>` / `<shape>` | ❌ `Shape XML is not supported here.` |
| `.zip`, `.amproj`, media | ❌ `Only effect XML can be imported.` |
| JSON, HTML, plain text | ❌ `Not XML.` |
| XML with `<!DOCTYPE>` or entities | ❌ `DOCTYPE is not allowed.` |
| Two or more root elements | ❌ `Exactly one effect per file.` |

Parser: `DOMParser` with `application/xml`, then check `doc.querySelector('parsererror')`, then
`doc.documentElement.tagName === 'effect'` and `doc.documentElement.parentNode === doc`.

## D.3 Validation pipeline (ordered, fail-fast, line-numbered errors)

| # | Check | Limit / rule |
| --- | --- | --- |
| 1 | Size | ≤ **64 KB** raw text |
| 2 | Encoding | valid UTF-8, no BOM issues |
| 3 | No DOCTYPE / no external entities | reject on sight |
| 4 | Single root, tag `effect` | as above |
| 5 | Required attrs | `id`, `name` non-empty |
| 6 | ID form | `[a-z0-9._-]{3,80}`; auto-namespaced to `custom.<slug>` if it collides |
| 7 | Params | tags in the allowlist: `spinner, slider, float, point, xyz, orient, color, selector, switch, section, tip, texture` |
| 8 | Textures | `srcType` in `content, buffer, comp, image`; `image` requires a `src` that resolves to a bundled resource — **no remote URLs** |
| 9 | Passes | ≤ 8; attrs `target, effect, src, blend` only |
| 10 | Shaders | ≤ 8, `type` in `fragment, vertex`, `precision` in `high, medium`, `group` numeric |
| 11 | Shader forbids | `#include`, `#extension`, `sampler3D`, `samplerCube`, `imageLoad`, `textureSize` on external, any `http://` / `https://` |
| 12 | GLSL compile | compiled against the real `ShaderRegistry` in an **OffscreenCanvas WebGL2** context; all groups must compile |
| 13 | Script | optional; ≤ 16 KB; no `fetch`, `XMLHttpRequest`, `import(`, `require(`, `eval`, `Function(`, `while(true)`, `document`, `window`, `localStorage`, `postMessage` |
| 14 | Script run | executed in the sandbox with a **hard 16 ms budget**; must return within budget on 3 test frames |
| 15 | Preview render | 3 frames on the standard test card (checker + text + gradient); must produce non-empty alpha |

Any failure returns the exact rule number, the line, and a one-line fix hint. The user can always see
**why** an effect was rejected.

## D.4 Storage and lifecycle

- Table `customEffects` in IndexedDB (mirror the existing `saveElementToDb` pattern in
  `src/store/storage.ts`): `{ uid, id, name, xml, source: 'paste'|'file', created, hash, enabled }`.
- Hash = SHA-256 of the normalised XML; importing the same effect twice offers **replace / keep both**.
- Library grid: thumbnail rendered from the test card at import time, name, source, delete, disable,
  export `.xml`.
- Custom effects appear in the effect browser under `Custom`, are searchable, and are **not** mixed into
  the 315 built-ins — a badge distinguishes them, and a "filter: custom only" toggle exists.
- Deleting a custom effect that a project references must **not** delete it from the project; mark the
  layer's effect as `missing` and offer to relink or remove.

## D.5 Security posture (this is the whole point of "only effects")

- Effects are **data plus sandboxed script**. The script never runs on the main thread — Track D depends
  on `ENGINE_PARITY.md` **P0-05** (worker sandbox with a wall-clock budget). Ship P0-05 first.
- No file system, network, DOM, storage or clipboard access from an effect script.
- No `src` pointing outside the bundled resource set — an effect cannot exfiltrate or beacon.
- The validator runs **before** the effect is persisted, so a rejected file never reaches the library.
- Importing is an explicit user action with a visible summary: name, params count, shader count, script
  present (yes/no), so nobody pastes a "shader" that is actually a 20 KB script.

## D.6 Acceptance

| Test | Expectation |
| --- | --- |
| A community effect XML (e.g. a simple blur variant) | imports, compiles, renders, appears in Custom |
| A project XML (root `<scene>`) | rejected at rule 4 with the project-file message |
| `<presets>` pack | rejected at rule 4 |
| 100 KB effect | rejected at rule 1 |
| XML with `<!DOCTYPE effect [...]>` | rejected at rule 3 |
| Effect whose script calls `fetch` | rejected at rule 13 |
| Effect whose script loops forever | rejected at rule 14, UI stays responsive |
| Effect with an un-compilable shader | rejected at rule 12 with the GLSL log |
| Same effect pasted twice | replace/keep-both prompt, no duplicate IDs |
| Delete a custom effect used by a project | project keeps the layer, marks effect missing |

# Open decisions (need a human, not an agent)

1. **Density default at ≥1280 px** — 1.1 UI scale is the recommendation; 1.15 is denser and bolder. Pick one.
2. **Keymap collisions** — `Tab` for layer inspector is aggressive (breaks tab-navigation). Keep it, or
   move to `Ctrl+L`?
3. **Custom effect namespacing** — `custom.<slug>`, or allow authors to claim
   `com.alightcreative.effects.<name>` so community effects can impersonate built-ins? Recommend
   **never** allow impersonation.
4. **Script support in custom effects** — allow (sandboxed, rule 13–14) or shader-only for v1? Shader-only
   is materially safer and covers most community effects.
