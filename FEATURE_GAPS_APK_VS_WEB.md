# FEATURE_GAPS_APK_VS_WEB

Feature audit of the web replementation against the **Alight Motion 5.0.280** APK
(`com.alightcreative.motion`, versionCode `1028519`, minSdk 24 / targetSdk 34).

The question this document answers: *what does the APK have that the web build does not, and what is
the smallest set worth building first?* It answers nothing else. It is not a bug list — bugs already
have owners in `ENGINE_PARITY.md`, `PREVIEW_CACHE_DEFECTS.md`, `GRAPH_EASING_AUDIT.md` and friends.

| Marker | Meaning |
| --- | --- |
| ✅ verified | read out of the APK **and** out of the web source in this session |
| ⚠️ predicted | APK side verified, web side reasoned from a grep or a type, not traced end to end |
| ❌ open | needs one APK capture or one measurement before it can be called |

> [!important] The APK is the ground truth, the web is the claim
> Every APK-side statement below names a class descriptor from `classes*.dex` or a `<string>` resource
> name from `resources.arsc`. Both are regenerated by
> `python scripts/audit/apk-inventory.py "<extracted-apk-dir>"` → `scripts/audit/out/`.
> Every web-side statement names `file:line` in `src/`.

## 0. The minimal set

Ten features are missing. Four of them matter; six are workflow polish. Nothing in the "already at
parity" section (§5) needs rebuilding — several earlier tickets assumed it was missing when it was not.

| # | Missing feature | Tier | Why it is on the list |
| --- | --- | --- | --- |
| **A1** | Nested scenes — Precompose + Elements | **A** | The APK's element model is a *scene reference*; the web's is a *layer copy*. Every AM project that uses elements imports wrong, permanently. |
| **A2** | Re-timing — Freeze / Loop / Stretch / Loop & Stretch / Blank | **A** | The web has one scalar `speed`. The APK re-times a whole scene, and a group with a retime cannot accept media. |
| **B1** | Script UI controls (`UIControl` slider/switch, `UILabel`) | B | Without them, scripted effects cannot expose their own parameters — the custom-effect lane dead-ends. |
| **B2** | Wave / oscillator animators | B | Property generators, not effects. Nothing in the web generates a sine on a property. |
| **B3** | Edge decorations (arrowheads, caps on open paths) | B | `LayerStroke` stops at cap/join/dash. |
| **B4** | Media crop modes — Fill / Fit / Stretch | B | The user has to hand-scale media; the APK has a one-tap crop button in the player. |
| **B5** | Align / Distribute (incl. distribute on timeline) | B | Zero implementation. Visible gap in any multi-select workflow. |
| **B6** | Clipping masks round-trip — `clippingMask` is read but never written | B | Read at `amXmlCodec.ts:559`, rendered by a real shader pass, then exported as `blending="mask"` — a dialect AM does not read. Every mask is lost on save. |
| **C1** | Built-in script assets (Move Along Path, Morph Path, Shake Parts, Grow Parts) | C | Six assets ship in the APK; none in the web. |
| **C2** | Image sequence **import** | C | Export only today; the APK ingests a numbered sequence. |
| **C3** | Preset preview | C | Web lists presets by name; APK opens a live preview screen. |

**Minimum for "a project made in AM behaves the same"**: A1, A2 and B6.
**Minimum for "a user does not notice a missing tool"**: A1, A2, B3, B4, B5, B6.

## 1. Tier A — structural gaps

### A1 — ✅ Nested scenes: Precompose and Elements

**APK evidence**

| Artefact | What it is |
| --- | --- |
| `scene.NestedSceneElementTypeImpl` | an element type that renders another `Scene` |
| `scene.NestedSceneElementKt$retimeNestedScene$1…7` | a nested scene carries its own retime state |
| `scene.NestedSceneClippingKt` | nested-scene clipping mode |
| `scene.PrecomposeType` | `precompose`, `precompose_dynamic_resolution`, `precompose_fixed_resolution` |
| `importer.projectpackage.ElementDownloadActivity` | elements are downloadable assets, not inlined copies |
| strings | `create_element`, `edit_linked_element`, `edit_original_element`, `element_properties`, `element_resolution`, `duplicate_element`, `delete_element` |

**Web state**

```ts
// types/project.ts:40-51 — no 'nested' / 'scene' / 'precompose' kind exists
export type LayerType = 'shape' | 'text' | 'image' | 'video' | 'audio'
                      | 'null' | 'camera' | 'group' | 'vector' | 'freehand';
```

```ts
// amXmlCodec.ts:549-557 — a nested <scene> is FLATTENED into group layers on import
const nestedScene = el.querySelector(':scope > scene');
const groupLayers = nestedScene
  ? Array.from(nestedScene.children)
      .filter((c) => LAYER_TAGS.has(c.tagName.toLowerCase()))
      .map((c, j) => parseXmlLayer(c, j, groupWidth!, groupHeight!, mediaMap))
  : undefined;
```

```ts
// types/project.ts:278-284 — "Elements" in the web are a flat layer clone
export interface SavedElement { id: string; name: string; createdAt: number; layers: Layer[]; }
// useEditorStore.ts:1020-1035 — saveSelectedAsElement() does structuredClone(sel)
```

**Consequence.** A project whose element is edited at the source — the APK's `edit_original_element`
flow — cannot be represented. The import is lossy in one direction only: geometry survives, the
reference does not. Two instances of the same element become two unrelated groups, and a nested retime
(A2) has nowhere to live.

**Minimal implementation.** This is the one change that touches the type system, the codec and the
renderer, so it needs to be scoped as its own ticket:

1. `LayerType` gains `'nested'`; `Layer` gains `sceneRef: { sceneId: string }` and
   `precompose: { mode: 'dynamic' | 'fixed'; width: number; height: number }`.
2. `Project` gains `scenes: Record<string, Scene>` (or `SavedElement` is promoted to a real scene with
   a `layers` root and its own resolution).
3. Renderer draws a nested scene into its own FBO at `precompose` resolution, then composites it like
   any other layer — reuse the group isolation path already in `renderer.ts` rather than a second
   compositor.
4. `amXmlCodec` round-trips `<embedScene>` instead of flattening it; `clippingMask` on a nested scene
   binds to `NestedSceneClippingKt`'s semantics, not to a sibling — the attribute itself is a separate
   defect, see **B6**.
5. UI: "Precompose selection" / "Create Element" on the group action bar; element insertion points at
   the scene, not at a cloned layer array.

**Acceptance**
- Import an AM project containing one element used twice → two `nested` layers sharing one `sceneId`.
- Edit the shared scene's text → both instances re-render on the next frame, one undo to revert.
- Export XML → the `<embedScene>` subtree survives, and a re-import produces the same `sceneId` count.
- Fixed-resolution precompose renders at its declared size regardless of the parent scene's size.

### A2 — ✅ Re-timing: Freeze, Loop, Stretch, Loop & Stretch, Blank

**APK evidence**

| Artefact | What it is |
| --- | --- |
| `scene.ReTimingMethod` | the enum behind the five menu entries |
| `scene.RetimedScene` | a scene wrapped in a time remap |
| `scene.timemapping.TimeMapping` | piecewise remap |
| `scene.timemapping.InterpolatedKeyframe` | keyframed remap points |
| `scene.timemapping.SpeedComputationKt` | speed integration / min-speed coercion |
| `scene.SceneElementKt$withAbsoluteTimingAndSpeedInScene` | element speed folded into scene time |
| strings | `retime_freeze`, `retime_loop`, `retime_stretch`, `retime_loop_stretch`, `retime_blank` |
| string | `media_cannot_be_added_in_group_details` — *"speed control has been applied to the group"* |

**Web state**

```ts
// types/project.ts:226
speed: Animatable<number>;
```

```ts
// animation.ts:295-303 — one scalar multiplier, numerically integrated
const speedProp = layer.speed;
if (speedProp && (speedProp.keyframes.length > 0 || Math.abs(speedProp.value - 1) > 1e-4)) {
  // Numerical integration of speed(u) over [0, normT] normalized so speed=1 maps 0..1
```

The UI exposes exactly that: a **Speed** slider with a keyframe row
(`TypeInspectors.tsx:374-395`, `LayerInspector.tsx:145`, `:352-355`).

**Consequence.** Five modes are unrepresentable. The APK's `retime_loop_stretch` — loop a 3 s clip
across a 9 s layer — is the single most-used of them, and it is also what makes `NestedSceneElementKt`
useful. `retime_freeze` (hold the first frame for N seconds) has no equivalent at all: setting
`speed = 0` divides by zero in the integration at `animation.ts:303` (`Math.max(0.01, …)` clamps it to
a near-static crawl, which is wrong, not frozen).

**Minimal implementation.** Keep `speed`; add a sibling on the layer:

```ts
retime?: {
  method: 'none' | 'freeze' | 'loop' | 'stretch' | 'loopStretch' | 'blank';
  sourceStartMs: number;   // in-point of the source window
  sourceEndMs: number;     // out-point
  /** loop: how many times to repeat before the layer ends, 0 = fill */
  repeats?: number;
};
```

`retime` composes *before* `speed` in `animation.ts`'s local-time resolution: `retime` maps layer time
to source time, then `speed` scales inside the source. That ordering is what makes `loopStretch` equal
to `loop` plus a stretch factor, matching the APK's single enum rather than five code paths.

**Acceptance**
- 3 s clip on a 9 s layer, `loopStretch` → content loops exactly 3× and ends on the last frame.
- `freeze` → every output frame after t=0 hashes identical.
- `blank` → layer renders nothing, timeline bar still occupies its slot.
- XML round-trip preserves the retime block; a group with a non-`none` retime refuses media insertion
  with the APK's own message.

## 2. Tier B — missing tools

### B1 — ✅ Script UI controls

`scene.animators.UIControl`, `UIControl$Slider`, `UIControl$Switch`, `UIControlSlider`,
`UIControlSwitch`, `UILabel`, `scene.scripting.ScriptEnv`, `ScriptArguments`, `ACScript` — a script can
declare its own sidebar: a labelled slider, a labelled switch.

Web: `scriptRuntime.ts` exposes exactly four entry points —
`runEffectScript` (`:194`), `getShapeCompiled` (`:246`), `evaluateShapePath` (`:263`),
`evaluateShapeHandles` (`:273`). There is no path from a script to a control.

**Minimal:** a script return value may include `ui: [{ kind: 'slider'; id; label; min; max; step }, { kind: 'switch'; id; label }]`; `EffectSettingsPanel` renders them after the declared params and feeds values back into `ScriptEnv`. Acceptance: a custom effect that returns one slider drives one parameter, and the slider value is saved in the project.

### B2 — ✅ Wave / oscillator animators

`WaveAnimators$FloatAnimatorSine`, `$FloatAnimatorSineMult`, `$Vector2DAnimatorSine`,
`$Vector2DAnimatorRandom`, `$Vector2DAnimatorTrangle`; `ColorAnimators$ColorAnimatorSine`,
`$SolidColorAnimatorRandom`.

These are **generators attached to a property**, not keyframes and not effects: amplitude, frequency,
phase, and for `SineMult`, a multiplier. The web has easing math (`animation.ts:65`, `:73`, `:78`,
`:104`) but no generator — a property is either a value or a keyframe list.

**Minimal:** `Animatable<T>` gains an optional `generator?: { kind: 'sine' | 'sineMult' | 'random' | 'triangle'; amplitude: number; frequency: number; phase: number }` evaluated additively on top of the base value in `evalAnimatable`. Acceptance: sine on rotation at 1 Hz, amplitude 15° → frame hashes match an APK capture at t = 0, 0.25 s, 0.5 s.

### B3 — ✅ Edge decorations

`scene.EdgeDecoration`, `EdgeDecorationType`, `EdgeDecorationDirection`, `EdgeDecorationKt`,
`KeyableEdgeDecoration`, `scene.StrokeEnd`.

Web `LayerStroke` (`types/project.ts:108-119`) is `cap | join | dash*` and nothing else. There is no
arrowhead, no tapered end, no per-end decoration, and no keyable decoration (the APK keys the
decoration itself).

**Minimal:** `LayerStroke` gains `startDecoration` / `endDecoration: { type: 'none' | 'arrow' | 'circle' | 'square' | 'taper'; size: Animatable<number>; direction: 'out' | 'in' | 'both' }`, drawn as a path extension in the shape pass. Acceptance: arrow on an open vector path renders at the correct tangent; XML round-trip keeps the element.

### B4 — ✅ Media crop modes

`scene.rendering.TextureCropMode`, `TextureCropModeKt`, `TextureCropModeButton`
(`com.alightcreative.common.compose.components.player.PlayerContainer.kt:105`), and strings
`media_crop_stretch_button`, `stretch_to_composition_area`, `stretch_to_screen`,
`template_media_crop_tooltip_body` — *"Tap to scale media: fit, stretch, or fill"*.

Web `MediaData` (`types/project.ts:171-184`) carries `naturalWidth/Height` and
`displayWidth/Height`. The only way to change framing is to scale the layer, which also scales stroke,
shadow and effects.

**Minimal:** `MediaData.cropMode: 'fit' | 'fill' | 'stretch'` applied as a UV transform at texture
bind time (not as a layer transform), plus the three-way button in the player. Acceptance: a 4:3 clip
in a 9:16 project, each mode produces a distinct and stable frame hash, and a layer with a stroke keeps
the stroke width under `fill`.

### B5 — ✅ Align / Distribute

`action_align_hcenter` (Center Horizontally), `action_align_vcenter`, `action_distribute_horizontal`,
`action_distribute_vertical`, `action_distribute_time` (Distribute on Timeline). Zero hits in `src/`
for any of them.

**Minimal:** a pure geometry pass in the store over the selection — align on the union bounds or on the
scene, distribute as equal gaps, distribute-in-time as equal spacing between first and last
`startTime`. One undo entry each. Acceptance: three layers at x = 100/400/1000 → distribute → equal
gaps; distribute-in-time over 0 s…6 s pushes the middle layer to 3 s.

### B6 — ✅ Clipping masks: `clippingMask` is read but never written

> [!warning] Correction against `TIMELINE_GROUPS_IMPORT.md` §R-5.1 / C-08
> That document states **"`clippingMask` is never parsed. Confirmed."** with a `grep -r "clippingMask"
> src/engine/ → 0 matches` as the proof. That is **no longer true** and was already false when checked
> here: `amXmlCodec.ts:559` reads the attribute and resolves it to `blendMode: 'mask'`, and
> `renderer.ts:2065-2081` runs a dedicated mask shader pass for it. The finding is downgraded from
> "not rendered" to "rendered on import, lost on export".

**APK evidence**

- Real AM exports put `clippingMask="true"` on the `<shape>` that acts as the matte — 6 layers in
  `free flip`, counted by the script at `TIMELINE_GROUPS_IMPORT.md:474`.
- `scene.NestedSceneClippingKt` — nested scenes carry their own clipping mode.
- Labels `blend_mask`, `blend_category_mask` exist as *display* strings.
- **`mask` is not a blend id.** The dex literal set is 23 `com.alightcreative.blend.*` ids and `mask`
  is not among them — AM encodes a mask as an *attribute on the element*, not as a blend mode.

**Web state** — three of four cases are right

| Stage | Code | Verdict |
| --- | --- | --- |
| Read | `amXmlCodec.ts:559-562` — `clippingMask="true"` → `blendMode: 'mask'` (or `'exclude'` when `blending="exclude"`) | ✅ |
| Render | `renderer.ts:2065-2081` — `maskProg`, `uBase` = scene, `uMask` = layer, `uExclude` flag | ✅ |
| Write | `amXmlCodec.ts:81` — `blending="${layer.blendMode}"` for anything ≠ `normal` | ❌ |

```ts
// amXmlCodec.ts:81 — the only blend attribute the writer knows about
const blendAttr = layer.blendMode !== 'normal' ? ` blending="${escapeXml(layer.blendMode)}"` : '';
```

So `blendMode: 'mask'` is exported as `blending="mask"`, and `clippingMask="true"` is **never
emitted**. Because `mask` is not one of AM's 23 blend ids, AM cannot read what the web writes; and
because the web never re-emits the attribute, an AM → web → AM round trip silently drops every mask.

**Consequence.** A masked reveal stack — a `wipe2` inside a clipping mask, the exact case named in the
earlier document — renders correctly in the web *until the project is saved as XML*. Then the matte is
gone. This is the one finding on the list that loses data rather than merely omitting a tool.

**Minimal fix** — ~6 lines, one function:

```ts
// amXmlCodec.ts:81 — restore the attribute dialect
const isMask = layer.blendMode === 'mask' || layer.blendMode === 'exclude';
const clipAttr = isMask ? ' clippingMask="true"' : '';
const blendAttr = isMask
  ? (layer.blendMode === 'exclude' ? ' blending="exclude"' : '')
  : layer.blendMode !== 'normal'
    ? ` blending="${escapeXml(layer.blendMode)}"`
    : '';
```

and append `${clipAttr}${blendAttr}` where `${blendAttr}` is emitted today.

**Acceptance**
- FG-B6a — Import an AM project with a `clippingMask="true"` layer, export XML, diff the attribute set:
  `clippingMask="true"` survives on the same element, `blending` stays absent unless it was `exclude`.
- FG-B6b — Round-trip twice: byte-identical output on the second pass (idempotence, not just correctness).
- FG-B6c — The 6 `free flip` mask layers still render identically in the web before and after the change
  (mask rendering must not be touched — only the writer).

**Not settled** — ❌ which layer the mask binds to. The web composites the mask against whatever is
already in `sceneFbo`, i.e. the mask affects everything drawn *beneath* it. Whether AM means "masks the
layer below", "masks the next sibling", or "masks the enclosing group" is still unproven; it is carried
as an open question in `TIMELINE_GROUPS_IMPORT.md:437` and remains open here. One capture settles it: a
two-shape probe with the mask on top, exported from AM at three frames.

## 6. Fix order

1. **B6 — mask export.** Six lines, and it is the only finding that *loses* data. It should not wait for
   A1/A2; ship it on its own.
2. **A2 — retime.** It is small, it is self-contained, and A1's nested scenes need it to be useful.
3. **A1 — nested scenes.** Type change → codec round-trip → renderer path → UI. Four PRs, in that order.
4. **B4 — crop modes.** Cheapest visible win; UV transform only, no model change.
5. **B3 — edge decorations.** Model + shape pass.
6. **B5 — align/distribute.** Pure store geometry, no renderer work — good parallel ticket.
7. **B1 — script UI**, then **B2 — wave animators.** Both extend `Animatable`/`ScriptEnv`; do them
   together so `Animatable` is touched once.
8. **C1…C6** in any order. C6 needs an APK capture first.

## 7. Open questions — one capture each

- ❌ **`<retime>` XML shape.** Attribute names and value encoding for the five methods. One AM export
  of a loop-stretched clip settles it; until then A2's codec work is guesswork.
- ❌ **`<embedScene>` + precompose attributes.** Which attribute carries `dynamic`/`fixed`, and where
  the nested scene's `width`/`height` live.
- ❌ **`<edgeDecoration>`.** Element name, child structure, and whether the size is keyable as a child
  `<value>` or an attribute.
- ❌ **Crop mode attribute.** `TextureCropMode` is a Kotlin enum; its XML serialisation is unknown.
- ❌ **`clippingMask` binding target.** The web composites the mask against everything already drawn
  beneath it; whether AM means "layer below", "next sibling" or "enclosing group" is unproven. Two-shape
  probe, mask on top, exported from AM at three frames. Carried over from `TIMELINE_GROUPS_IMPORT.md:437`.
- ⚠️ **Blend id drift.** The APK literals are `…blend.diff`, `…blend.colormultiply`, `…blend.luminance`,
  `…blend.softoverlay`; the web's `BlendModeId` has `difference`, `multiply`, `luminosity`, and no
  `softoverlay`. If the renderer falls back to `normal` on an unknown id, four modes silently degrade
  on import. **Check one XML before touching the call** — presets may use short names, not full ids.
- ⚠️ **`Smoothing`** may be an internal drawing algorithm rather than a user setting. If it is
  internal, C6 is a fidelity question, not a feature.
- ⚠️ **`MotionPathInfo`** — motion-path overlay in the preview. Present in the dex, unclear whether it
  is a user-visible overlay or an internal hit-test structure.
